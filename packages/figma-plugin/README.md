# Keyline Icons for Figma

Search the set inside Figma and drop an icon on the canvas. 503 names, three
styles, MIT.

Two ways into Figma exist and they solve different problems. A published library
hands a team the component sets from the design file, versioned, with the
container and style variants as dropdowns. This plugin hands *anyone* a searchable
set with no library, no plan requirement and no file to duplicate, which is how
Lucide and Hugeicons both reach people. Neither replaces the other.

## Files

```
manifest.json   what Figma reads
code.js         main thread: insert, name, place, select
ui.html         search, styles, grid. All of the UI, no build step
icons.json      generated by pipeline/build-data.mjs. Never hand-edit
```

No `package.json` and no dependencies: Figma loads these files directly, and
there is nothing here for a bundler to do that `__html__` does not already do.

## Running it locally

1. Figma desktop app, `Plugins` → `Development` → `Import plugin from manifest…`
2. Pick `packages/figma-plugin/manifest.json`.
3. Run it from `Plugins` → `Development` → `Keyline Icons`.

`manifest.json` has no `id`. Figma assigns one when the plugin is registered for
publishing, and writing a placeholder in by hand is how you end up publishing
under someone else's. Local import does not need it.

## Where the icons come from

`ui.html` fetches `icons.json` from jsDelivr at startup rather than bundling it:

```
https://cdn.jsdelivr.net/gh/keyline-icons/keyline-icons@main/packages/figma-plugin/icons.json
```

A plugin update goes through Figma's review before it reaches users, so bundling
the set would put every icon release behind that queue. A push to `main` reaches
the CDN on its own. The cost is jsDelivr's branch cache, roughly 12 hours, and a
network dependency the manifest has to declare in `networkAccess`. Pin a tag in
place of `@main` if a release needs to land the moment it is cut.

**The URL in `ui.html` is a published contract.** Renaming the repo, moving it to
an organisation or moving this file breaks every installed copy, and there is no
way to fix an installed copy except by publishing an update. Check it points at
the repo you actually publish from before the first release.

This copy of `icons.json` carries the keywords as well as the geometry, because
the plugin reads exactly one URL and cannot go back for `lib/icon-keywords.json`.
That is the only difference from the CLI and MCP bundles.

## Behaviour worth knowing

**`currentColor` is swapped for black on insert.** Figma's SVG importer has no
cascade to resolve a CSS keyword against, so the exports arrive unpainted if it
is left in. `code.js` substitutes it.

**An insert lands centred in the selected frame**, or centred in the viewport
when the selection is not a frame or component. Sections and instances
deliberately fall through: a section's children keep absolute page coordinates
and an instance refuses `appendChild`, so honouring either would put the icon
somewhere the user did not point at.

**Search matches the curated words too.** `arrow-down` is reachable by "south"
and "descend" because those live on the component set's description in Figma,
baked out by `pipeline/build-keywords.mjs`. Keywords are keyed by base name, so
`square-arrow-down` reads `arrow-down`'s words.

**A style with no matches says so.** Duotone and fill need a fillable region and
some glyphs have none, so an empty grid is usually coverage rather than a failure.
The count of names matching in another style is shown instead of nothing.
